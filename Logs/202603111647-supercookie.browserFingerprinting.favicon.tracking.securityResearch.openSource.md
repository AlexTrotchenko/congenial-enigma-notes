# Supercookie - Browser Fingerprinting via Favicons

## Overview

Supercookie demonstrates a browser tracking technique using favicons to assign unique identifiers to visitors. Unlike traditional cookies, this ID persists through incognito mode, cache clearing, browser restarts, OS reboots, VPN usage, and ad blockers. It exploits how browsers cache favicons separately from regular browsing data. **This is a security research/educational project** to raise awareness about this tracking method.

## How It Works

1. **Favicon Cache (F-Cache)** — Browsers cache favicons separately from regular browser cache, with entries including URL, favicon ID, and TTL

2. **Identification via cache probing** — When a browser requests a page:
   - If favicon is cached → no additional request made
   - If not cached → browser requests favicon from server

3. **Binary encoding** — Server creates multiple subdomain/path combinations, each with unique favicons. The pattern of which favicons are cached vs. requested creates a unique binary fingerprint

4. **Persistence** — F-Cache survives actions that would clear regular tracking:
   - Incognito/private mode ✅ detected
   - Clear cookies ✅ survives
   - Clear browser cache ✅ survives
   - Close browser ✅ survives
   - Restart OS ✅ survives
   - Use VPN ✅ survives
   - Ad blockers ✅ survives

## Quick Start (Self-Hosted Demo)

**Docker:**
```bash
git clone https://github.com/jonasstrehle/supercookie
cd supercookie/server
# Edit .env with your domain
docker-compose up
```

**Node.js:**
```bash
git clone https://github.com/jonasstrehle/supercookie
cd supercookie/server
# Edit .env with localhost:10080
node --experimental-json-modules main.js
# Open http://localhost:10080
```

## How to Clear Your Supercookie

| Browser | Clear Method |
|---------|-------------|
| Chrome (Win) | Delete `C:\Users\<user>\AppData\Local\Google\Chrome\User Data\Default` |
| Safari (macOS) | Delete contents of `~/Library/Safari/Favicon Cache` |
| Edge (macOS) | Delete `~/Library/Application Support/Microsoft Edge/Default/Favicon*` |

## Notes & Considerations

⚠️ **For educational and demonstration purposes only.** This demonstrates a real tracking vulnerability. Brave browser has patched this (as of v1.19.92). The technique achieves 100% identification accuracy when browsers are vulnerable. The project gained significant media attention (Vice, Gizmodo, TechRadar, etc.) and was covered by security researcher Bruce Schneier. Created by a German student as a two-day research project. The favicon cache is fundamentally designed for UX (fast icon loading) but creates a privacy-hostile side effect.
